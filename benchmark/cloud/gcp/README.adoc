= GCP Benchmark Infrastructure

This directory prepares Experiment 015 without creating infrastructure by
default. The committed Flox lock provides the benchmark tools and the exact
ClickHouse 26.3.17.110 binary used by the local baseline.

== Boundaries

- `network/` defines the private benchmark VPC, subnet, and IAP-only SSH rule.
- `image/` builds a dependency-only Debian image on disposable discounted
  capacity.
- The image contains no corpus, credentials, ClickHouse data, or tenant state.
- Applying OpenTofu or running `packer build` creates billable shared resources
  and requires explicit approval.

The image builder has an ephemeral external address for outbound package-cache
access, but SSH is allowed only through Google's IAP range. Benchmark database
nodes will use private addresses and are defined separately after the image is
validated.

== Cost-free validation

[source,shell]
----
flox activate -- tofu -chdir=benchmark/cloud/gcp/network init -backend=false
flox activate -- tofu -chdir=benchmark/cloud/gcp/network validate

flox activate -- packer init benchmark/cloud/gcp/image/image.pkr.hcl
flox activate -- packer validate \
  -var project_id=lighthouse-508219 \
  -var network=lighthouse-benchmark \
  -var subnetwork=lighthouse-benchmark-us-central1 \
  benchmark/cloud/gcp/image/image.pkr.hcl
----

The template defaults to project-metadata user `wuddarwin` and private key
`~/.ssh/gcp`. Override `ssh_username` and `ssh_private_key_file` when another
operator builds the image. The private key is read from the workstation and is
never copied into the image or repository. The current key's public fingerprint
is `SHA256:8Va99u4/RSyII6p6Udi0a9tV44byqF6G3UjH/P79yf8`.

`tofu plan` contacts GCP and must be reviewed before apply. Packer's GCP plugin
currently exposes its legacy `preemptible` switch rather than the newer Spot
provisioning-model field. GCP rejects a maximum runtime on that legacy model, so
the short image build uses on-demand capacity with a one-hour maximum runtime
and deletion termination action. The Stage A serving topology will use actual
Spot VMs through OpenTofu. Automatic deletion is a last-resort cost guardrail,
not a substitute for supervising the build.

== Approved execution order

. Apply and preserve the reviewed network plan.
. Build the golden image with the one-hour-capped on-demand builder.
. Verify the image metadata and run the ClickHouse smoke test on a disposable
  instance.
. Provision the Stage A Spot database and load-generator topology from the
  validated image.
. Upload only the explicitly approved corpus to the private regional bucket.
. Run the Spot rehearsal, preserve artifacts, and destroy serving resources.
. Repeat the accepted workload on on-demand capacity.
