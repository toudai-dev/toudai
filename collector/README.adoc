= Lighthouse Collector

The bounded OpenTelemetry Collector distribution that runs the owned `lighthouse` exporter.
It was lifted from Experiment 021
(`rfd/0001/experiments/021-hybrid-layout-collector-integration/harness/component`, left in
place as evidence). `main.go` is an `otelcol.NewCommand` entry point over stock components at
the pinned versions plus `lighthouseexporter`.

[source,sh]
----
make collector-build   # target/collector/lighthouse-collector
make collector-test
----

== Pins

`go.mod` and `go.sum` carry the Experiment 021 pins unchanged: `otelcol-contrib` components
v0.161.0, Collector core modules v1.67.0, `clickhouse-go/v2` v2.47.0, Go 1.26. `go list -m all`
matches `results/go-modules.txt` of that experiment apart from the module path. ClickHouse is
pinned to 26.8.2.7-lts by `flake.nix`.

The distribution still includes the stock `clickhouseexporter` and `transformprocessor` that
Experiment 021 used for its stock-path probes; they can be dropped once nothing needs them.

== Exporter

`lighthouseexporter` validates a whole export request, writes the canonical payload row, then
the serving row, into the tables in link:../clickhouse/README.adoc[`clickhouse/schema`]. Queue,
retry, and timeout come from `exporterhelper`. Beyond the Experiment 021 options it takes
`routing_epoch` (default `1`), the Decision 0001 D4 stamp written on every serving row.
The exporter relies on a gateway pipeline that injects the trusted `lighthouse.workspace_id`,
`lighthouse.dataset`, and `lighthouse.scope_source` resource attributes before it; the
Experiment 021 `collector-gateway.yaml` is the reference configuration.
