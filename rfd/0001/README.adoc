== Architecture summary

Lighthouse provides Scuba-style recent-data exploration over logs, spans, and structured application events through one logical event model. Native metrics remain separate. Accepted events remain reconstructable at full resolution; ClickHouse is query-serving state backed by a durable replay and archive boundary. Bounded accelerators improve interactive queries without making raw retained fields unqueryable.

== Design principles

* Preserve accepted source events and disclose approximation, completeness, and freshness independently.
* Require tenant, dataset, and bounded time range for interactive queries.
* Keep derived storage bounded and retain raw fallback.
* Treat tenant policy, privacy, workload isolation, durability, and recovery as product correctness.
* Use measured evidence before committing storage, scaling, and latency choices.

== Dependency order

. Establish reproducible experiments and product thresholds.
. Define the product event contract, durable acceptance, archive, and replay semantics.
. Implement tenant policy and metadata observations.
. Implement truthful query semantics and bounded acceleration.
. Validate replication, recovery, workload isolation, cold tiers, and larger retained volumes.

Experiment results may revise design sections, but every checklist item has exactly one implementation-section owner.

== Cross-cutting exit criteria

RFD 0001 remains in discussion. The MVP contract is ready to commit only when:

* Experiment 011 reaches a documented terminal result and its multi-day query,
  restart, and workload-isolation evidence is incorporated;
* the user workflow and p50/p95 latency, freshness, retention, concurrency, and
  cost targets are explicit;
* acceptance, retry, deduplication, archive, and replay semantics are decided;
* cardinality and privacy defaults have concrete per-tenant budgets and
  observable rejection behavior;
* one service can emit the versioned envelope, replay into a clean serving
  table, and prove event/payload checksums;
* raw, accelerated, approximate, and incomplete responses expose consistent
  diagnostics; and
* the comparison, group-by, histogram, percentile, and exact-event drill-down
  workflow has been tested with an operator rather than inferred from SQL
  benchmarks alone.
