== Architecture summary

Lighthouse provides Scuba-style recent-data exploration over logs, spans, and structured application events through one logical event model. Native metrics remain separate. The PoC uses OpenTelemetry Collectors with direct ClickHouse ingestion and object-store overflow/catch-up. Canonical retention and backup/restore support reconstruction; independent all-event archival remains an explicit decision. Bounded accelerators improve interactive queries without making raw retained fields unqueryable.

== Design principles

* Organize datasets under workspaces within accounts; ingestion keys and telemetry isolation are workspace-scoped.
* Preserve accepted source events and disclose approximation, completeness, and freshness independently.
* Require tenant, dataset, and bounded time range for interactive queries.
* Keep derived storage bounded and retain raw fallback.
* Treat tenant policy, privacy, workload isolation, durability, and recovery as product correctness.
* Use measured evidence before committing storage, scaling, and latency choices.

== Dependency order

. Define the PoC workload, pass/fail thresholds, event contract, and acceptance semantics.
. Build a deterministic emitter and enforce tenant authorization and ingestion policy.
. Demonstrate OTLP ingestion, raw querying, overflow/catch-up, and canonical-data reconstruction.
. Demonstrate the operator workflow, then bounded acceleration with raw fallback.
. Exercise mixed tenants, cancellation, and small-topology replicated recovery.
. Only then expand retention, topology, cold-tier execution, and production qualification.

Experiment results may revise design sections, but every checklist item has exactly one implementation-section owner.

== PoC completion gate

The PoC must demonstrate one reproducible vertical slice:

....
OTLP -> Collector authentication/validation -> ClickHouse -> query/drill down
                         |                        |
                         +-> overflow -> catch-up +-> reconstruct/restore
....

Use a small deterministic corpus before repeating large retained-volume tests.
Each required milestone must record its fixture, command, expected result,
failure cases, and observed result in an experiment under `experiments/`.
Performance gates require prospective workload and numeric thresholds; the
historical benchmark medians are characterization, not implicit SLOs.

The implementation companions distinguish PoC-required milestones from later
validation and production qualification. Completed historical experiments remain
evidence, not evidence that the application milestone is implemented. The
link:acceptance-and-replay.adoc[Collector-first acceptance plan] requires measured
OTLP acknowledgement, loss, duplicate, and recovery behavior. Neither queue
admission nor protocol compatibility alone establishes durable acceptance.

PoC completion requires the emitter and operator tests in the product plan,
Collector/overflow/reconstruction tests in the acceptance plan, raw and accelerated
semantic tests in the query plan, authorization and bounded-work tests in the
tenant plan, and small-topology failure tests in the replication plan. Independent
health telemetry must expose failures even when ClickHouse is unavailable.

Provider comparisons, 100 TB loading, cross-zone qualification, and 24-to-72-hour
soaks do not block this PoC. They remain necessary where applicable before a
production readiness claim. Passing the PoC does not establish production SLOs.

== Cross-cutting exit criteria

RFD 0001 remains in discussion. The MVP contract is ready to commit only when:

* the completed Experiment 011 query baseline is incorporated, and separate
  restart, merge-time, and workload-isolation tests close its explicit gaps;
* the user workflow and p50/p95 latency, freshness, retention, concurrency, and
  cost targets are explicit;
* acceptance, retry, deduplication, archive, and replay semantics are decided;
* cardinality and privacy defaults have concrete per-tenant budgets and
  observable rejection behavior;
* one service can emit the versioned envelope, replay into a clean serving
  table, and prove event/payload checksums;
* raw, accelerated, approximate, and incomplete responses expose consistent
  diagnostics; and
* the comparison, group-by, histogram, percentile, and exact-event drill-down
  workflow has been tested with an operator rather than inferred from SQL
  benchmarks alone.
