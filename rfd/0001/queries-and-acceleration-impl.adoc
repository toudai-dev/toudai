== PoC-required: raw query semantics

Depends on the versioned event contract, authenticated query scope, and the
acceptance plan's materialized fixture. Validate raw results against independent
fixture expectations before using them as acceleration comparison anchors.

* [ ] Define the event filter, grouping, time-series, heatmap, percentile, and raw-result query contract.

* [ ] Compare companion-type, tagged-value, and native typed Map encodings against the typed fixture; verify lossless canonical round-trip, type-sensitive filters/groups, numeric rather than lexical ordering, presence semantics, aggregate type errors/overflow, and lossless response encoding; record storage and execution cost before selecting the PoC DDL.
+
Experiment 019 compared the companion-type and tagged-value encodings on a
deterministic typed fixture with expectations computed from the typed inventory
(and the conversion helper checked against the pinned exporter's stored values).
Both support the representation-level semantics when a mapping step supplies the
types: typed filters and group keys, numeric ordering, presence semantics, exact
`Int64` values, and lossless canonical round-trip. The companion type Map adds
about 1.2% of the serving Map bytes and keeps the stock serving strings, while
the tagged-value Map adds about 4.7% and more group-by work. Unsupported-operation
rejection, aggregate type errors, and integer-overflow rejection were enforced
by the harness query prototype, not by ClickHouse; plain `sum(Int64)` wraps, so
the query layer must implement type filtering, explicit errors, and guarded
integer aggregation. Lossless response encoding and PoC DDL selection remain
open (the service layer and the decision record own them). See
link:experiments/019-typed-canonical-storage.adoc[Experiment 019].
+
*Open:* the native typed Map alternative was not evaluated by Experiment 019, and
PoC DDL selection remains open. A concrete layout such as `Map(String, Int64)` /
`Map(String, Float64)` plus string and bool Maps and explicit presence/empty
bookkeeping may serve typed values without a stringly-typed value Map, but native
numeric columns do not by themselves satisfy the typed-value contract: a missing
key lookup returns the type default, `sum(Int64)` still wraps, and a key present
with another type is indistinguishable from a missing key without presence
metadata. This section owns the comparison and the PoC DDL selection; Experiment
020 is the bounded follow-up evaluation.
+
Experiment 020 evaluated the native typed Map alternative on the same fixture
and corpora. Two equal-contract layouts — per-type value Maps with a full
per-key type sidecar, and per-type value Maps with a key-only map for the
canonical-only types (bytes, array, map) and explicit empty — satisfy the
fixture's typed surface, including non-finite doubles (present in the `Float64`
Map; only their comparison and aggregation are rejected by the harness
prototype) and span scope attributes. Known-type queries can guard directly on
the matching typed value Map, so the minimal layout need not scan five Maps for
a typed filter, ordering, or sum; only presence and grouping for a key whose
type is unknown in advance need the union/type expression, where the sidecar is
cheaper in CPU but the union was not uniformly worse in compressed bytes. Native
typed Maps reduced total compressed bytes by 4.9-11.2% versus the companion
baseline including payload (21.0-25.9% excluding payload for the minimal
layout), and known-type filter reads were 3.8-4.6x smaller because the companion
layout must read its whole string value Map; splitting the small, type-diverse
resource and scope namespaces into typed Maps cost more than one string Map.
`sum(Int64)` still wraps; type filtering, overflow rejection, and
contributing-value counts remain query-layer obligations. PoC DDL selection,
planner support for the minimal layout's union/type expressions, and
retained-scale read behavior remain open. See
link:experiments/020-native-typed-map-comparison.adoc[Experiment 020].
+
Experiment 021 exercised the minimal native typed layout (per-type record value
Maps plus the canonical-only kind map, with string Maps and companion type Maps
for resource and scope) through a real OTLP -> Collector -> ClickHouse path
instead of a direct-insert harness. Stored type identity, presence, extremes,
non-finite and negative-zero carriage, unsupported-type marking, namespace
separation, and canonical round-trip all held for logs and spans, and known-type
readback used direct map guards on the matching typed Map rather than scanning
five Maps. This is real-path representation conformance on a tiny corpus: it adds
no storage, cost, or latency evidence, does not select DDL, and leaves the
query-layer error, overflow, and unknown-key union obligations open. See
link:experiments/021-hybrid-layout-collector-integration.adoc[Experiment 021].
