== PoC-required: raw query semantics

Depends on the versioned event contract, authenticated query scope, and the
acceptance plan's materialized fixture. Validate raw results against independent
fixture expectations before using them as acceleration comparison anchors.

* [ ] Define the event filter, grouping, time-series, heatmap, percentile, and raw-result query contract.

* [ ] Compare companion-type, tagged-value, and native typed Map encodings against the typed fixture; verify lossless canonical round-trip, type-sensitive filters/groups, numeric rather than lexical ordering, presence semantics, aggregate type errors/overflow, and lossless response encoding; record storage and execution cost before selecting the PoC DDL.
+
Experiment 019 compared the companion-type and tagged-value encodings on a
deterministic typed fixture with expectations computed from the typed inventory
(and the conversion helper checked against the pinned exporter's stored values).
Both support the representation-level semantics when a mapping step supplies the
types: typed filters and group keys, numeric ordering, presence semantics, exact
`Int64` values, and lossless canonical round-trip. The companion type Map adds
about 1.2% of the serving Map bytes and keeps the stock serving strings, while
the tagged-value Map adds about 4.7% and more group-by work. Unsupported-operation
rejection, aggregate type errors, and integer-overflow rejection were enforced
by the harness query prototype, not by ClickHouse; plain `sum(Int64)` wraps, so
the query layer must implement type filtering, explicit errors, and guarded
integer aggregation. Lossless response encoding and PoC DDL selection remain
open (the service layer and the decision record own them). See
link:experiments/019-typed-canonical-storage.adoc[Experiment 019].
+
*Open:* the native typed Map alternative is not evaluated. A concrete layout such
as `Map(String, Int64)` / `Map(String, Float64)` plus string and bool Maps and
explicit presence/empty bookkeeping may serve typed values without a
stringly-typed value Map, but native numeric columns do not by themselves satisfy
the typed-value contract: a missing key lookup returns the type default,
`sum(Int64)` still wraps, and a key present with another type is
indistinguishable from a missing key without presence metadata. Whether that
bookkeeping (and its handling of explicit empty, bytes, and nested values) costs
less than the companion type Map is unmeasured. This section owns the comparison
and the PoC DDL selection; a bounded follow-up evaluation owns the measurements.

* [ ] Implement a planner that chooses raw, projection, metadata, or aggregate paths without changing query semantics.

* [ ] Implement independent accuracy, path, and completeness controls; table-test exact rollup selection, raw approximate execution with permission, unknown source coverage, missing execution shards, and budget failures without silent downgrade.

* [ ] Preserve and validate known/unknown sampling metadata and provenance; test identical retained events with different declared probabilities produce unchanged observed-event aggregates and explicit adjustment=none, while invalid metadata and unsupported correction requests never produce falsely corrected results.

* [ ] Return plan diagnostics including selected storage path and approximation mode.

* [ ] Define ingestion watermarks, expected shard coverage, and complete versus bounded-latency execution independently of exact versus approximate math.

* [ ] Execute the required raw query shapes against the deterministic fixture; verify expected rows/aggregates and diagnostic accuracy, including rejected and failed requests.
