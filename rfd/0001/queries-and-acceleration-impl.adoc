== PoC-required: raw query semantics

Depends on the versioned event contract, authenticated query scope, and the
acceptance plan's materialized fixture. Validate raw results against independent
fixture expectations before using them as acceleration comparison anchors.

* [ ] Define the event filter, grouping, time-series, heatmap, percentile, and raw-result query contract.
+
The filter, grouping, and count/sum parts of this contract are defined and
enforced by the typed-value item below. Time-series bucketing, heatmaps,
percentiles, raw-result rows, and the HTTP surface that returns a response
remain open, so this item stays unchecked.

* [x] Enforce the PoC typed-value contract in the raw query layer (Rust library, ClickHouse SQL generation over the Experiment 021 layout; no HTTP API yet): type-matched predicates with no implicit coercion, group keys that include type, guarded `Int128` integer sums with overflow rejection, contributing-value counts separate from event counts, presence by Map key membership, explicit unsupported-operation errors for bytes, arrays, maps, and non-finite floats, and plan diagnostics for the raw path.
+
`src/query/` validates a request against
link:product-contract.adoc#_poc_typed_value_contract[the PoC typed-value
contract] (`plan`), generates a parameterized main statement (`sql`) that guards
on Map key membership and accumulates integers in `Int128`, and, for double
comparisons, generates a separate parameterized probe that counts excluded
non-finite values. The result layer turns returned values into contract errors:
an `Int128` total outside `Int64` is an `IntegerOverflow`, never a wrapped sum;
a sum with no contributing value is absent rather than zero; an incompatible
non-empty value fails the aggregate unless an explicit type filter (or a
comparison against a literal of the aggregate's type) excludes it; bytes,
arrays, maps, and non-finite floats fail grouping and float aggregation. Integers
and unsigned counts use typed decimal strings in response JSON. Table tests in
`tests/experiment021_*.rs` run the generated SQL under `clickhouse local`
against the Experiment 021 fixture (rows exported from the 021 harness's
independent expectations by `scripts/export-fixture021-rows.py`, tables from
`serving-tables.sql` unchanged) and check the Experiment 019/021 expectations:
int 1, double 1.0, and string `"1"` are three filters and three groups; missing,
explicit empty,
`""`, `false`, and `0` stay distinct; `2^53 + 1` and the `Int64` limits stay
exact; the SQL-backed cases reject two `Int64::MAX` values and the full 12-int
fixture total, while the `sum-a + sum-b + sum-c` wrap case is checked directly
at the result-interpreter boundary; and the span duration aggregate reports 4
contributing, 5 excluded, and 2 timing errors for the fixture's 9 spans.
Known-type filters read only the matching typed Map; presence, grouping, and an
untyped sum read every record Map, as Experiment 020 anticipated. The immutable
fixture makes the main statement and non-finite probe deterministic here; a
future executor must run both against one snapshot before claiming the same
diagnostic consistency during concurrent ingestion.
+
Scope limits of this item: resource and scope attributes are stored as text with
a companion type Map, so only exact string, bool, and int equality, presence,
type tests, and grouping are accepted for them (anything else is an explicit
`UnsupportedForNamespace` error); non-finite stored floats never satisfy a
numeric comparison, and the response reports how many events that skipped
(`non_finite_excluded`) instead of failing; group values order by
`(type, text)`, not numerically; and the column names follow the Experiment 021
`serving-tables.sql` (`workspace_id`, `ts`) until the Decision 0001 DDL lands.
The presentation of an unavailable duration remains a rendering decision.

* [x] Compare companion-type, tagged-value, and native typed Map encodings against the typed fixture; verify lossless canonical round-trip, type-sensitive filters/groups, numeric rather than lexical ordering, presence semantics, aggregate type errors/overflow, and lossless response encoding; record storage and execution cost before selecting the PoC DDL.
+
Experiment 019 compared the companion-type and tagged-value encodings on a
deterministic typed fixture with expectations computed from the typed inventory
(and the conversion helper checked against the pinned exporter's stored values).
Both support the representation-level semantics when a mapping step supplies the
types: typed filters and group keys, numeric ordering, presence semantics, exact
`Int64` values, and lossless canonical round-trip. The companion type Map adds
about 1.2% of the serving Map bytes and keeps the stock serving strings, while
the tagged-value Map adds about 4.7% and more group-by work. Unsupported-operation
rejection, aggregate type errors, and integer-overflow rejection were enforced
by the harness query prototype, not by ClickHouse; plain `sum(Int64)` wraps, so
the query layer must implement type filtering, explicit errors, and guarded
integer aggregation. Lossless response encoding and PoC DDL selection remain
open (the service layer and the decision record own them). See
link:experiments/019-typed-canonical-storage.adoc[Experiment 019].
+
link:decisions/0001-poc-physical-layout.adoc[Decision 0001] selects the PoC
DDL from this comparison. Lossless response encoding is owned by the query
contract item above; the layout comparison itself is complete.
+
*Resolved by Experiment 020 and Decision 0001:* the native typed Map
alternative was not evaluated by Experiment 019 and PoC DDL selection was open
until the decision record. A concrete layout such as `Map(String, Int64)` /
`Map(String, Float64)` plus string and bool Maps and explicit presence/empty
bookkeeping may serve typed values without a stringly-typed value Map, but native
numeric columns do not by themselves satisfy the typed-value contract: a missing
key lookup returns the type default, `sum(Int64)` still wraps, and a key present
with another type is indistinguishable from a missing key without presence
metadata. This section owns the comparison and the PoC DDL selection; Experiment
020 is the bounded follow-up evaluation.
+
Experiment 020 evaluated the native typed Map alternative on the same fixture
and corpora. Two equal-contract layouts — per-type value Maps with a full
per-key type sidecar, and per-type value Maps with a key-only map for the
canonical-only types (bytes, array, map) and explicit empty — satisfy the
fixture's typed surface, including non-finite doubles (present in the `Float64`
Map; only their comparison and aggregation are rejected by the harness
prototype) and span scope attributes. Known-type queries can guard directly on
the matching typed value Map, so the minimal layout need not scan five Maps for
a typed filter, ordering, or sum; only presence and grouping for a key whose
type is unknown in advance need the union/type expression, where the sidecar is
cheaper in CPU but the union was not uniformly worse in compressed bytes. Native
typed Maps reduced total compressed bytes by 4.9-11.2% versus the companion
baseline including payload (21.0-25.9% excluding payload for the minimal
layout), and known-type filter reads were 3.8-4.6x smaller because the companion
layout must read its whole string value Map; splitting the small, type-diverse
resource and scope namespaces into typed Maps cost more than one string Map.
`sum(Int64)` still wraps; type filtering, overflow rejection, and
contributing-value counts remain query-layer obligations. PoC DDL selection,
planner support for the minimal layout's union/type expressions, and
retained-scale read behavior remain open. See
link:experiments/020-native-typed-map-comparison.adoc[Experiment 020].
+
Experiment 021 exercised the minimal native typed layout (per-type record value
Maps plus the canonical-only kind map, with string Maps and companion type Maps
for resource and scope) through a real OTLP -> Collector -> ClickHouse path
instead of a direct-insert harness. Stored type identity, presence, extremes,
non-finite and negative-zero carriage, unsupported-type marking, namespace
separation, and canonical round-trip all held for logs and spans, and known-type
readback used direct map guards on the matching typed Map rather than scanning
five Maps. This is real-path representation conformance on a tiny corpus: it adds
no storage, cost, or latency evidence, does not select DDL, and leaves the
query-layer error, overflow, and unknown-key union obligations open. The
experiment also fixes the span-duration count contract for a future aggregate: a
span with missing or reversed timing stores an unavailable (NULL) duration and is
excluded from contributing-value counts, a reversed span is still preserved,
searchable by its supplied timestamps, and counted in an explicit timing-error
count, and a valid zero duration contributes with value 0 (the fixture-derived
expectation is 4 contributing / 5 excluded / 2 timing errors of the fixture's 9
span rows; the same-workspace log rows live in `serving_logs` and are never part
of a span count). That count contract is agreed; the query-layer aggregate is
implemented by the typed-value item above, and the presentation of an
unavailable duration remains open. See
link:experiments/021-hybrid-layout-collector-integration.adoc[Experiment 021].
