= Experiment Records

link:../README.adoc[RFD 0001]

Experiment records preserve enough context to reproduce and interpret a result.
Use a zero-padded sequence and descriptive name, for example
`001-json-vs-map-1tb.adoc`.

Each record should contain:

. *Status and date* — planned, running, completed, invalidated, or superseded.
. *Question* — the specific uncertainty being tested.
. *Hypothesis* — optional, but written before inspecting results.
. *Environment* — CPU model, core/thread count and frequency; RAM capacity and
   configured speed; disk models, topology, filesystem, capacity, and measured
   throughput/IOPS; ClickHouse version/settings; caches; and relevant repository
   revision. Include `_local-hardware-baseline.adoc` for runs on the local host
   and state which storage path the experiment exercised. Never substitute a
   device's advertised limit for a measured speed or apply a later topology's
   measurement retroactively.
. *Dataset* — source, time range, transformation revision, rows, logical input
   bytes, and expected limitations.
. *Method* — schema revision, load procedure, query fixture IDs, repetitions,
   and cold/warm cache policy.
. *Commands* — runnable commands or links to versioned scripts.
. *Results* — raw measurements and artifact locations, not only conclusions.
. *Interpretation* — what the results support and what they do not prove.
. *Follow-ups* — unresolved questions and the decision records that consume
    the evidence.

Do not overwrite prior measurements when rerunning an experiment under different
conditions. Add a new run or record and link the relationship.
