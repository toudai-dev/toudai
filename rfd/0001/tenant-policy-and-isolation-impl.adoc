= Tenant Policy And Isolation implementation

Checklist ownership: link:tenant-policy-and-isolation.adoc[Tenant Policy And Isolation].

== PoC-required: authorization and policy

Depends on the event/tenant contract and product fixture. Authentication and
authorization precede both acceptance and query execution; workload-isolation
tests follow the working raw and accelerated paths.

* [ ] Define account/workspace/dataset records and workspace-scoped ingestion keys, including multiple keys per workspace, rotation, revocation/cache-expiry behavior, and separate write/read/admin permissions.
* [ ] Implement key-derived trusted workspace scope before Collector batching; verify dataset routing stays within it, unknown datasets fail, and producer scope attributes cannot override ownership or leak credentials.
+
Experiment 018 implemented a *static* credential-to-workspace binding with the
tested stock components (`routing` connector on the `Authorization` header plus a
`resource` processor before batching). Producer scope attributes could not
override it, an unknown credential was rejected with HTTP 401, and no credential
text reached any attribute map. In the pinned source `bearertokenauth` attaches no
identity and the fixture confirmed that `auth.*` context is empty, so with these
components key-derived resolution, dataset routing, and rotation/revocation
behavior remain custom work; other stock authenticators were not evaluated.
Cross-workspace isolation through a shared downstream batch was not exercised.
See link:experiments/018-collector-compatibility.adoc[Experiment 018].
+
Experiment 021 verified real credential validation inside the tested custom
distribution (`bearertokenauth`; a request with no token or a wrong token
received HTTP 401 with no stored rows) and a static synthetic
credential-to-workspace binding on the hybrid layout, with the trusted scope
injected before canonicalization so both the canonical identity and the serving
row carry it. Producer attributes could not override the trusted workspace or
dataset on resource, scope, or record. The forged-scope probe showed the
documented limitation that a producer forging the trusted-scope marker itself is
indistinguishable from injected scope for the mapping component, and one request
mixing a forged-scope group with a group missing the scope wrote nothing at all,
so an invalidating rejection covers the whole request. That marker check is a
pipeline-composition guard, not provenance or authentication: the tested
configuration upserts the reserved workspace/dataset/marker keys in both
workspace `resource` processors and references the owned exporter only from those
stamped pipelines, and the exported ClickHouse endpoint must be unreachable
except through them (an operational control the harness cannot assert). One real
downstream batch carried both workspaces, but isolation of those rows downstream
of the write is a query-layer question that remains open, and catch-up provenance
(whether a replayed object passes the same stamping and scope checks) was not
tested. Key-derived resolution, rotation/revocation, and dataset routing
rejection remain out of scope. See
link:experiments/021-hybrid-layout-collector-integration.adoc[Experiment 021].

* [ ] Test workspace authorization across ingestion, queries, metadata, and exact payload retrieval using sibling workspaces in one account and a workspace in another account with colliding dataset/event/trace names and IDs; reject cross-workspace access on every path the slice provides, including shared downstream batches; repeat for overflow and catch-up when those paths exist in qualification.

== Qualification: policy integration, privacy, deletion, and isolation

These items are required before a production readiness claim and before RFD 0001 moves to `committed`. They do not block the PoC vertical slice defined in link:README.adoc#_poc_completion_gate[the PoC completion gate]; a PoC pass does not mark any of them complete.

=== Authorization and policy

* [ ] Integrate authentication, validation, redaction, quotas, and cached versioned tenant policy with Collector gateways before normal and overflow export; reuse available components and justify any custom extension.

* [ ] Implement the dataset and field-policy registry.

* [ ] Specify and test new-request rejection after key revocation and workspace deletion separately from already admitted backlog handling; verify catch-up retains original ownership without requiring the producer credential.

=== Canonical privacy and deletion

* [ ] Define canonical post-policy payload semantics and transformation versioning; inject secret markers into attributes/body and verify absence from retained payloads, queues under our control, overflow, derived data, and diagnostic logs.
* [ ] Choose retention clock, duration, late/future-event policy, and logical/physical expiry deadlines; test just inside/at/outside expiry and prove retries, catch-up, and restore do not renew record lifetime.
* [ ] Implement whole-workspace/dataset deletion fences and completion barriers; test stale policy caches, in-flight queries/writes, colliding recreated names, and backlog replay without resurrecting deleted scope.
* [ ] Inventory purge progress and backup expiry; restore a pre-deletion backup into isolation, apply current deletion state, and verify no deleted raw, payload, metadata, or aggregate result is exposed. Fail closed if current deletion state cannot be recovered.

=== Bounded exploration and work

* [ ] Implement bounded single-authority admission and versioned policy caching; test unknown/expired policy, registry outage, revocation within the proposed 60-second staleness bound, queue exhaustion, and independent dashboard/raw budgets without claiming uncoordinated per-replica limits are global quotas.

* [ ] Implement stream-derived field presence, type, cardinality, top-K, value-size, and growth-rate observations without enumerating high-cardinality values.

* [ ] Run a small mixed-tenant fixture with dashboard queries, expensive raw scans, and ingestion; verify prospective queue/execution/freshness limits, observable rejections, and cancellation of leaf work after deadlines.
