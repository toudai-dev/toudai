== PoC-required: emitter and operator workflow

The fixture definition precedes ingestion implementation. The operator test
depends on the acceptance, raw query, and minimal acceleration milestones.

* [ ] Build one deterministic fixture emitter using standard OTel SDK/OTLP for two tenants with logs, spans, application events, and a native-metric compatibility sample; include invalid records and independently computed expected contents/checksums, and verify reproducibility without proprietary batch receipts.

* [ ] Prove logs, spans, and application events can be queried together.

* [ ] Prove trace rendering includes span events and correlated logs.

* [ ] Specify and table-test the typed canonical envelope through standard OTLP and Collector processing: missing/empty/string/false/zero, integer versus string versus float, integers above 2^53 and signed limits, non-finite floats, bytes, nested collections, namespace collisions, duplicate keys, case sensitivity, and missing/invalid durations; preserve supported content and expose explicit errors for unsupported operations.
+
Experiment 018 table-tested exactly these cases through the stock Collector and
recorded the outcome: the OTLP receiver preserves every received type, but the
stock ClickHouse exporter stores all attribute values as strings (so integer 1,
double 1.0, and string "1" are indistinguishable; arrays and maps become JSON
text that collides with producer strings; explicit-empty and empty-string merge),
keeps duplicate keys in the `Map`, drops span scope attributes, and converts a
negative span duration into a `UInt64` underflow. A Lighthouse canonical envelope
must therefore be implemented outside the stock schema. See
link:experiments/018-collector-compatibility.adoc[Experiment 018].
+
Experiment 019 established where that envelope can be built: the pinned stock
exporter cannot insert a canonical payload column (`create_schema: false` leaves
it at its DEFAULT/type default), the tested stock expressions cannot produce a
typed canonical payload or a per-key type map (the natural per-key expression
does not parse, and the pinned OTTL function inventory has no conditional or
typed marshal), and a Map-carried payload plus `MATERIALIZED` projections stores
the payload twice. Conditional `where` statements across multiple passes, other
processors, and components outside the pinned distribution were not evaluated.
The envelope therefore needs a mapping component outside the stock schema
(processor or exporter) placed after trusted-scope injection; the harness
prototype's envelope round-tripped losslessly against the typed inventory and
matched the exporter's stored serving values. See
link:experiments/019-typed-canonical-storage.adoc[Experiment 019].
+
Experiment 021 table-tested the same semantic surface through a real
OTLP -> Collector -> ClickHouse path with the owned exporter: strict
int/double/string separation, missing versus explicit-empty versus empty string,
false and zero, integers above 2^53 and the `Int64` extrema, non-finite doubles
and negative zero, bytes and nested collections marked as unsupported in the
serving row but preserved in the canonical payload, namespace separation
including span scope, duplicate/conflicting keys, and lossless canonical
retrieval with reconstruction of the serving values against the fixture
inventory. That is representation conformance for logs and spans through the
component; the operator workflow, metrics, and the query layer's unsupported-
operation errors remain open. See
link:experiments/021-hybrid-layout-collector-integration.adoc[Experiment 021].
+
Span timing through the same path follows the accepted preserve-and-flag policy:
a span whose start or end is unset (OTLP encodes an unset timestamp as 0) or whose
end precedes its start is preserved with its supplied timestamps and an
unavailable (NULL) duration plus an explicit diagnostic; missing timing takes
precedence over the reversed classification, so a missing start never fabricates a
duration from epoch 0 and a missing end is never read as reversed. Missing timing
and a valid zero duration stay distinct (`missing` with NULL versus `ok` with
zero). The canonical payload keeps the supplied timestamps and omits the
unavailable duration, and the fixture-derived contributing/excluded/error counts
(4/5/2 of the fixture's 9 span rows, with the same-workspace log rows never part
of a span count) are recorded as the agreed count contract for duration
aggregates. The service/query/UI implementation of that contract and the
presentation of an unavailable duration in a waterfall or dashboard remain open,
and the earlier rejection behavior measured before the policy change is superseded
in that experiment's report.

* [ ] Provide a minimal operator-facing client and record an operator completing time comparison, grouping, heatmap/percentile inspection, outlier identification, and exact-event drill-down against the fixture; verify results against its known events.
